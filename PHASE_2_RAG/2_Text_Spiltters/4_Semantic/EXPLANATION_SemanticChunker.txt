================================================================================
SEMANTIC CHUNKER - DETAILED EXPLANATION
================================================================================

OVERVIEW:
---------
The SemanticChunker is the most advanced text splitting method available in 
LangChain. Unlike previous splitters that use static rules, SemanticChunker 
uses embeddings and semantic similarity to split text at meaningful boundaries 
where the topic or meaning changes. It creates chunks based on the actual 
semantic content, not just character counts.

KEY CONCEPT:
------------
Instead of splitting by:
  ✗ Character count (dumb)
  ✗ Separators like newlines (simple)
  
It splits by:
  ✓ MEANING CHANGES - when topic/semantics shift significantly
  ✓ CONTEXT PRESERVATION - keeps related content together
  ✓ SEMANTIC SIMILARITY - detects actual content shifts

ARCHITECTURE:
--------------
Semantic Chunker uses THREE main components:

1. EMBEDDINGS MODEL:
   - Converts text into numerical vectors
   - Captures semantic meaning
   - Default: sentence-transformers/all-MiniLM-L6-v2
   - Example: "Dog" and "Puppy" have similar embeddings

2. BREAKPOINT DETECTION:
   - Measures similarity between consecutive chunks
   - Detects large drops in similarity
   - Marks these as split points

3. THRESHOLD/BREAKPOINT STRATEGY:
   - Determines what counts as a "significant" change
   - Types: percentile, standard_deviation, aggregate
   - Controls splitting sensitivity


KEY PARAMETERS:
---------------
1. embeddings:
   - Embedding model to use
   - Example: HuggingFaceEmbeddings()
   - Must be a valid embedding model

2. breakpoint_threshold_type (str):
   - "percentile": Uses percentile of similarity scores
   - "standard_deviation": Uses std deviation from mean
   - "aggregate": Custom aggregation method
   - Default: "percentile"

3. breakpoint_threshold_amount (float/int):
   - For percentile: 50 = median (0-100)
   - For std_deviation: 3 = 3 sigma (units of std dev)
   - Controls sensitivity of splitting
   - Higher = fewer splits, Lower = more splits

4. min_chunk_size (int):
   - Minimum chunk size to create
   - Prevents creating tiny chunks
   - Default: 1 (every sentence)

5. max_chunk_size (int):
   - Maximum chunk size before forced split
   - Optional hard limit


HOW IT WORKS - DETAILED PROCESS:
--------------------------------
Step 1: INPUT
        - Receive document text
        - Initialize embedding model

Step 2: SENTENCE SEGMENTATION
        - Split text into sentences (base units)
        - Each sentence will be analyzed

Step 3: EMBEDDING GENERATION
        - Convert each sentence to embedding vector
        - Capture semantic meaning numerically

Step 4: SIMILARITY CALCULATION
        - Calculate similarity between consecutive sentences
        - Use cosine similarity or similar metric
        - Produces similarity scores (0-1 range)

Step 5: BREAKPOINT DETECTION
        - Compare similarity scores against threshold
        - Mark sentences where similarity drops sharply
        - These become split points

Step 6: CHUNK FORMATION
        - Group consecutive sentences between breakpoints
        - Create semantic chunks
        - Each chunk covers one coherent topic

Step 7: OUTPUT
        - Return list of semantically meaningful chunks
        - Each represents a topic/idea unit


BREAKPOINT THRESHOLD TYPES:
---------------------------

1. PERCENTILE MODE:
   - breakpoint_threshold_type="percentile"
   - breakpoint_threshold_amount=30-90 (typically 50)
   
   How it works:
   • Calculate all similarity scores
   • Find the percentile (e.g., 50th = median)
   • Split where score falls below this percentile
   
   Example:
   Similarity scores: [0.8, 0.75, 0.3, 0.85, 0.9]
   50th percentile = ~0.80
   Similarity drops below 0.80 at position 2 (0.3)
   → Create breakpoint after position 2

2. STANDARD DEVIATION MODE:
   - breakpoint_threshold_type="standard_deviation"
   - breakpoint_threshold_amount=1-5 (typically 2-3)
   
   How it works:
   • Calculate mean and std dev of similarities
   • Split where score is N std devs below mean
   • More statistical approach
   
   Example:
   Mean similarity: 0.75, Std Dev: 0.15
   Threshold (2 sigma): 0.75 - (2 × 0.15) = 0.45
   When similarity < 0.45 → Create breakpoint

3. AGGREGATE MODE:
   - Custom aggregation strategy
   - Most flexible but requires configuration


EXAMPLE WALKTHROUGH:
--------------------
Text with topic changes:

"Farmers were working hard in the fields, preparing the soil and planting 
seeds for the next season. The sun was bright, and the air smelled of earth 
and fresh grass. The Indian Premier League (IPL) is the biggest cricket league 
in the world. People all over the world watch the matches and cheer for their 
favourite teams. Terrorism is a big danger to peace and safety. It causes 
harm to people and creates fear in cities and villages."

STEP 1: Sentence Segmentation
S1: "Farmers were working hard in the fields..."
S2: "The sun was bright..."
S3: "The Indian Premier League (IPL) is the biggest cricket league..."
S4: "People all over the world watch the matches..."
S5: "Terrorism is a big danger to peace and safety..."
S6: "It causes harm to people..."

STEP 2: Generate Embeddings
E1: [0.1, 0.5, 0.2, ...] (farming topic)
E2: [0.15, 0.48, 0.18, ...] (farming topic)
E3: [0.8, 0.1, 0.7, ...] (sports topic) ← DIFFERENT!
E4: [0.78, 0.12, 0.68, ...] (sports topic)
E5: [0.2, 0.9, 0.1, ...] (security topic) ← DIFFERENT!
E6: [0.22, 0.88, 0.12, ...] (security topic)

STEP 3: Calculate Similarity
Sim(E1, E2) = 0.98 ✓ (very similar - farming)
Sim(E2, E3) = 0.15 ✗ (big drop - topic change)
Sim(E3, E4) = 0.95 ✓ (very similar - sports)
Sim(E4, E5) = 0.20 ✗ (big drop - topic change)
Sim(E5, E6) = 0.97 ✓ (very similar - security)

STEP 4: Apply Threshold (e.g., 50th percentile ≈ 0.56)
Below threshold:
• Sim(E2, E3) = 0.15 < 0.56 → BREAKPOINT
• Sim(E4, E5) = 0.20 < 0.56 → BREAKPOINT

STEP 5: Form Chunks
Chunk 1: S1 + S2 (farming topic)
Chunk 2: S3 + S4 (sports topic)
Chunk 3: S5 + S6 (security topic)

Result: Perfect semantic chunking!

CODE EXAMPLE:
=============

from langchain_experimental.text_splitter import SemanticChunker
from langchain_huggingface import HuggingFaceEmbeddings

# Initialize embedding model
embeddings = HuggingFaceEmbeddings(
    model_name='sentence-transformers/all-MiniLM-L6-v2'
)

# Create semantic chunker with percentile threshold
chunker_percentile = SemanticChunker(
    embeddings=embeddings,
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=50  # 50th percentile (median)
)

# Create semantic chunker with std deviation threshold
chunker_std = SemanticChunker(
    embeddings=embeddings,
    breakpoint_threshold_type="standard_deviation",
    breakpoint_threshold_amount=3  # 3 sigma
)

# Split text into documents
chunks = chunker_std.create_documents([sample_text])

# Each chunk is a Document object with metadata
for chunk in chunks:
    print(chunk.page_content)


# Example with different sensitivity levels:

# MORE AGGRESSIVE SPLITTING (more chunks, smaller size)
fine_chunker = SemanticChunker(
    embeddings=embeddings,
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=30  # Lower threshold = more splits
)

# LESS AGGRESSIVE (fewer chunks, larger size)
coarse_chunker = SemanticChunker(
    embeddings=embeddings,
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=75  # Higher threshold = fewer splits
)

EMBEDDING MODEL SELECTION:
---------------------------
Good choices:
• all-MiniLM-L6-v2 (recommended - fast and accurate)
• all-MiniLM-L12-v2 (more powerful)
• all-mpnet-base-v2 (highest quality)
• multilingual-e5-base (multilingual support)

Trade-offs:
• Smaller models = Faster but less accurate
• Larger models = Slower but better semantic capture
• Consider embedding dimension (384 vs 768)
• CPU/GPU availability for inference

THRESHOLD TUNING GUIDE:
-----------------------
Start with default values and adjust:

TOO MANY CHUNKS (over-splitting):
  → Increase breakpoint_threshold_amount
  → Increase percentile value
  → Increase std deviation multiplier

TOO FEW CHUNKS (under-splitting):
  → Decrease breakpoint_threshold_amount
  → Decrease percentile value
  → Decrease std deviation multiplier

Experimentation steps:
1. Start with percentile=50 or std_dev=2
2. Review sample chunks
3. Adjust based on quality
4. Test with actual retrieval task
5. Measure retrieval accuracy

COMPARISON WITH OTHER SPLITTERS:
--------------------------------
CharacterTextSplitter:
  - Pros: Fast, simple
  - Cons: No semantic awareness
  - Best for: Quick prototypes

RecursiveCharacterTextSplitter:
  - Pros: Respects structure, balanced
  - Cons: No semantic meaning
  - Best for: Most general cases

LanguageTextSplitter:
  - Pros: Code-aware
  - Cons: Code only
  - Best for: Source code

SemanticChunker:
  - Pros: True semantic boundaries, best quality
  - Cons: Slow, expensive
  - Best for: Production systems needing high quality

HYBRID APPROACH:
----------------
Combine for best results:
1. Use Recursive splitter for initial segmentation
2. Use SemanticChunker for final refinement
3. Combine speeds up processing
4. Maintains semantic quality
5. Better cost/quality trade-off
